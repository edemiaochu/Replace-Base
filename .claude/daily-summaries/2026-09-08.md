## 工作内容

### display-test-app「首次打开文件 ~80s」根因定位并修复(主要工作)
- 症状:重启程序后第一次打开文件卡 ~80s,同会话第二次快;对比 desktop-viewer-test 打开快
- **排除项**(均实测):
  - 瓦片缓存:确认瓦片缓存是 `.bim` 旁 `.Tiles` 侧车 SQLite 库(非 `%LOCALAPPDATA%`),两 app 共享同一份,冷热与症状无关(打点:viewport 0.14s/首帧 0.45s)
  - 鉴权:66 次 `szewtwin.electron.auth.getAccessToken-native-testId` "No handler registered" 报错是伴随症状——`IMJS_NO_ELECTRON_AUTH` 禁用后照样卡 80s
- **打点定位**:app 内 `BriefcaseConnection.openFile` 78.4s,其后 ViewList 0.04s/默认视图 0.04s/ScreenViewport 0.14s/首帧 0.45s——慢全部在 open 本身;裸 node 直调 core-backend(无 Electron/前端/鉴权)`StandaloneDb.openFile` RW=82.6s、`SnapshotDb.openFile` RO=81.6s
- **根因链**:open → `IVaultDb` 构造 → `[_resetIVaultDb]`(IVaultDb.ts:619)→ `GeoCoordConfig.loadForIvault` → `loadDefaultDatabases`(每进程仅首次,`_defaultDbsLoaded` 标志)→ `ws.getContainer` → CloudSqlite 连 `geocoord-workspace.szewtwinjs.org`(域名无 DNS)→ Windows DNS 超时重试 ≈80s 同步阻塞——正好解释"每进程首次慢、后续快"
- **验证**:`szewtwin/core/gcs/disableWorkspaces=true`(GeoCoordConfig.ts:39 开关)后同操作 **0.03s**
- **修复落地**:Settings 无 env 桥接机制,在 `Backend.ts`(startup 后)加 3 行 env 桥 `addDictionary` 注册 `szewtwin/core/gcs/disableWorkspaces`;`.env` 加 `IMJS_DISABLE_GCS_WORKSPACES = True` 生效(用户已加)
- 文件:`itwinjs-core/test-apps/display-test-app/src/backend/Backend.ts`(唯一代码改动,backend 已重新 build)、`.env`
- 排查弯路(复测时避坑):4.bim 等旧 native 建的文件报 `InvalidProfileVersion` 开不动,测试用 9 月新建的 NewIVault*.bim;并行第二实例报 "Profile already in use"(profileName 锁);强杀实例会留 profile 僵死锁造成后续卡顿假象(删 `profiles/<name>` 目录恢复)
- 复现工具(一次性,已删):`.env` 加 `IMJS_STANDALONE_FILENAME=<file>` 自动打开 + `electron --enable-logging=stderr` 抓 renderer console;裸 node 探针直调 core-backend 计时
