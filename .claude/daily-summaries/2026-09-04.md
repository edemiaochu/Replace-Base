## 用户提问与解答

### Q1: `cross-env` 不是内部或外部命令,这是什么问题?
- display-test-app 的 node_modules 不存在(core/backend 有、它没有,某次安装中断/被删),`rush install` 后恢复;该仓库必须用 rush/rushx,不能直接 npm start

### Q2: Electron 启动报 ERR_MODULE_NOT_FOUND(.../@openid/appauth/built/src/authorization_request),这是什么问题?
- `@openid/appauth@1.4.0` 是坏包:标了 `type: module` 但编译产物内部 import 不带 `.js` 扩展名,Electron 主进程(CJS)require 它时 Node 按 ESM 严格解析 → 崩;1.3.2 是正常 CJS 包

### Q3: viewer 为啥会拉取 1.4.0 的包?
- 依赖方(core-electron 5.9.1、electron-authorization 0.22.3)声明 `^1.3.2`,浮动范围允许 1.4.0;1.4.0 于 2026-08-19 才发布
- lockfile 是解析快照:itwinjs-core 的 lockfile 生成早于 1.4.0 发布 → 锁 1.3.2;viewer 的 lockfile 在发布后重新生成过(rush update 或首次安装)→ 取"当时最新" 1.4.0
- `rush install` 忠实现有 lockfile 不会升级;只有 `rush update`/首装才重新解析——所以不是最近的 install 干的,是 lockfile 里早就写着
- 两仓库都没有钉版本机制(无 pnpmfile.js、preferredVersions 无 appauth)

### Q4: viewer 中不能用 1.4.0 吗?
- 不能:这个发布本身坏了,`require()` 走 require(esm) 严格解析挂,真正的 ESM `import` 同样因无扩展名挂;Node 无开关补救(`--experimental-specifier-resolution=node` 已移除,Electron 主进程加自定义 loader 也不现实)
- 1.4.0 已是最新版,没有修复版可升;唯一出路是 pnpm patch 给产物补扩展名——为上游 bug 魔改自己仓库不值,钉回 1.3.2 即可(功能上 1.4.0 相比 1.3.2 只是模块格式迁移,无新功能)

### Q5: 前端报 35070 "The Schema 'BisCore' has an unsupported namespace .../dm/32/dmschema",这是什么问题?
- native 5.9.17 序列化 schema 的 `$schema` 为 `.../dmschema` 结尾,TS(ecschema-metadata,发布版与源码相同)正则只认 `.../ecschema` 结尾——分叉全局 EC→DM 改名时把 native 里 URL 尾段也改了
- 证据:native 二进制 grep 直接命中 `dmschema` 字符串;两仓库 native 同为 5.9.17 精确 pin
- 修复点:`core/ecschema-metadata/src/Metadata/Schema.ts:831` 正则放宽为接受两种尾段;改 native 需重编二进制,代价大得多

### Q6: 运行日志 CloudSqlite 反复 GET geocoord-workspace.szewtwinjs.org/gcs/manifest.bcv 并报 SSL connect error,为啥会这样尝试?
- 这是 GCS(地理坐标系统)参考库的按需下载:viewer 打开空间 iVault 后,后端 `GeoCoordConfig.loadForIvault`(core/backend/src/GeoCoordConfig.ts:93)按默认 settings(`szewtwin/core/gcs/default/databases`)连接 GCS 云容器(manifest.bcv 为容器清单,内含全球坐标系/基准参考库,供地理定位/背景地图/基准转换用)
- 失败根因:该域名**无 DNS 解析**(curl 实测 Could not resolve host)——分叉把 itwinjs.org 改名成 szewtwinjs.org,但这个服务在新域名下从未部署;日志里的 "SSL connect error (rc=1)" 是 native curl 对连接失败的归类,连不上后 CloudSqlite 后台循环重试(r1, nRetry=1)
- 影响:纯 Info 级后台日志,看图/编辑/新建功能不受影响;只有 GCS 相关功能(设地理坐标系、背景地图地理对齐、基准转换)在服务恢复前不可用;任何空间文件打开都会触发,与新建功能无关
- 处理:①不管它;②设 `szewtwin/core/gcs/disableWorkspaces=true` 关掉加载(GeoCoordConfig.ts:39 有开关);③需要 GCS 功能则把 `szewtwin/core/gcs/databases` 指向自建/镜像容器

### Q7: 可以在 viewer 里面配置环境变量吗?
- 可以,两层机制(均已在用):
  - **后端(运行时)**:`main.ts:23` dotenv-flow 加载应用根目录 `.env`(支持 .env.local/.env.development 覆盖);应用专属变量前缀 `SZEWTWIN_VIEWER_`(AppInfo.ts:9,getAppEnvVar 读取);第三方包在主进程读的 IMJS_* 运行时变量也走此通道
  - **前端(构建时)**:`vite.config.ts:48` `envPrefix: "IMJS_"`,仅 IMJS_ 前缀变量暴露给 renderer(import.meta.env),改动需重启 dev server/重新 build;SZEWTWIN_VIEWER_* 对 renderer 不可见
- 限制:GCS 的 disableWorkspaces 是 appWorkspace Setting 而非环境变量(Settings.ts 无 env 桥接);要用 env 控制需在 main.ts 加两三行把 SZEWTWIN_VIEWER_DISABLE_GCS 映射到 settings
